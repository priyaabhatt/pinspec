# Before values name a token only when the code evidently uses it

pinspec sees computed values (`232px`, `#6B7280`), not the source that produced them, yet the agent needs to know which class or token to edit. So a before value is named only when there's evidence the code uses that token: a length gets a class only if the element's class list has the utility that produces it (`w-58`, `md:w-58`, `dark:w-58`, `px-4`; state variants like `hover:` don't count), and a colour gets a token only if it matches one exactly, preferring the element's own colour class when several tokens share a hex. Everything else, including arbitrary values like `w-[232px]` and lengths that merely equal a scale step, is shown raw. We rejected naming every value that happens to equal a step, because it would tell the agent to edit a class the code doesn't have. Class names are only used on Tailwind sites, recognised by Tailwind v4's `--spacing` token; elsewhere tokens are written `var(--name)` and lengths stay raw, even when a site's token names look like Tailwind's. All naming goes through the design system module (`src/lib/designSystem.ts`), so the card, the picker and the handoff image always write a value the same way.
